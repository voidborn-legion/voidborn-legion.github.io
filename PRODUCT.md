# AION 2 Academy · Voidborn

## Platform
web

## Stack
User-selected VitePress and Vue 3, GitHub Pages, GitHub Actions and Pages CMS. Public repository: voidborn-legion/voidborn-legion.github.io. No own domain or server; no paid actions without consent.

## Users
Initially German-speaking AION 2 players and Voidborn guild members looking for practical progression guides, system explanations and checklists on desktop and mobile. Prepare English terminology and linked translations; release German first, then reviewed English guides.

## Product Purpose
A readable gaming wiki that helps readers find their next useful action, with sources and review status visible.

## Operating Context
Existing content lives in the connected AION 2 Academy Discord Studio. Migration into Academy drafts is the next phase, in the separate content chat; preserve source IDs, comments, image placeholders and internal links. Never change the source Studio as a side effect. The development chat owns the plugin, implementation, redesign and technical acceptance. See architecture/DELIVERY-PLAN.md for current milestones.

## Capabilities and Constraints
Current foundation: VitePress website, Vue Academy Studio and Academy Manager connected to the protected Academy service. Core draft editing, image uploads, comments, tasks and versioning have been live tested. Next: complete German draft migration, redesign using real content, public navigation for multiple guides per category, user administration and targeted publication before the public relaunch. Do not invent verified game values or publish private editorial feedback. Guide prose stays separate from Vue components. The public site must not render unpublished drafts; draft files in the public repository remain publicly readable.

Future optional player profiles remember character and confirmed progress in protected storage. A character check must first prove available public NCSOFT fields, distinguish unknown data from missing progress, and explain recommendations using reviewed guide rules. Character lookup must not imply ownership. The public website remains useful without an account or character service. Defer the unfinished pet-only game-data menu rather than presenting it as a universal database.

Visitors may sign in but see Studio navigation only after authorization. Studio and plugin share server-enforced permissions. GitHub login is first; Discord, verified email invitations and account linking follow later. Publication is a separate permission and explicit workflow. Private profile and grant data must not be stored in public GitHub files.

Future separate equipment adviser: accept manual item/slot, enhancement and effect/soul-binding values, class/role, goal and optional budget; later prefill available fields from a character. Compare keeping, inheritance and supported full/item-stat reroll options using reviewed guide rules. Explain which values to preserve or improve and distinguish practical targets from game limits. Verify transfer losses, action availability, costs and probabilities before making precise recommendations. Equipment guides must explain these decisions, including full-ring versus individual-stat rerolls. This adviser is not yet implemented and does not gate the first public relaunch.

## Future Discovery, Not Current Scope

The user wants concrete questions answered from maintained Academy guides, with direct source-section links, optional longer explanations and relevant videos. Test a small internal AI-assisted search after a representative guide is reviewed; keep ordinary search and reading usable independently. Any public API-backed assistant requires explicit cost decisions and service-enforced usage limits. Only approved content appropriate to the requesting user's permissions may enter answers; distinguish game region/version, actual verification dates and unresolved claims. Retrieval cannot make outdated source content current.

A later optional in-game companion could open by shortcut, accept a player-provided screenshot or manual equipment values and reference the same guide knowledge. Character APIs, network-derived data, overlay compatibility, game rules and anti-cheat constraints require separate feasibility investigation; no support or permission is assumed. Monetization is an idea, not an approved commercial commitment. Website and editorial workflow remain the foundation; no overlay implementation in the current Studio concept.

- Separate verified mechanics from editorial recommendations.
- Preserve provenance and editorial work.
- Keep the public site usable without accounts or a backend.
